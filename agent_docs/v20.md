# v20: entity tokens, per-token action heads, custom PPO loop

Step 3 of `roadmap.md`, built from `step3_handoff.md` (September 2026). v17-v19 code is unchanged;
v20 is a separate env, network, trainer and player.

## Files
- `envs/rl_player_v20.py`: `Featurizer` (observations), `action_mask` / `action_to_order` /
  `order_to_action` (14 actions), `RLEnvV20` (two-agent `PokeEnv` with timeouts),
  `hold_requests_until_log` (see gotcha 9), `disable_turn_snapshots`.
- `networks/v20_policy.py`: `V20Net`.
- `training/ppo_v20.py`: learner, workers, evals, pool, checkpoints. All settings in `CONFIG`.
- `players/v20_player.py`: `V20Policy` (network + featurizer), `V20Player` (a poke-env Player),
  `load_opponent` (v20 `.pt` or SB3 zip).
- `eval/v20_eval.py`: evaluation games; `eval/ppo_test.py` routes `.pt` models there.
- Checks: `tools/check_v20_env.py`, `tools/check_v20_damage.py`, `tools/check_v20_selfplay.py`,
  `tools/check_v20_resume.sh`. Throughput: `tools/bench_sb3.py` (the SB3 loop, without touching v19).
- `data/gen9_randbats_sets.json`: pinned copy of the fork's random-battle sets (used for the
  opponent Atk estimate), so the observation doesn't change with the Showdown checkout.

## Observation
`Featurizer.featurize(battle)` returns `(idx int64[140], flt float32[1259], mask bool[14])` from
that battle's player's point of view; it works for either side of a battle.
- 12 Pokémon tokens: 6 own in `battle.team` order (token k is switch action 8 + k), then the
  opponent's revealed Pokémon in first-seen order and "unrevealed" placeholders.
  - Index fields: species, item (unknown / none distinct), ability (unknown distinct), tera type
    (own from the request; opponent's hidden until it terastallizes), current types, 4 moves,
    the last move used this stint.
  - Floats (86): side, placeholder, revealed, active, fainted, HP, level, 6 stats (own actual from
    the request, opponent estimated), status with sleep/toxic counters, boosts, tera/item/ability
    known flags, turns in, first turn (from the log), protect counter, recharge, charging,
    switch-in hazard damage, grounded, type matchups vs the other active, speed share, own PP
    (from the request), 30 volatile flags, Protosynthesis/Quark Drive stat.
  - Opponent stats: level from the details, 85 EVs / 31 IVs / neutral nature; 0 Atk when no
    random-battle set consistent with the revealed moves uses Attack (exact once 4 moves are
    known; about 92% right before), 0 Spe once Trick Room or Gyro Ball is revealed.
- 4 move tokens (`battle.available_moves[i]`, the move behind actions i and 4 + i): move and
  effective type (Tera Blast, Weather Ball, -ate abilities, ...), BP, accuracy, category,
  priority, PP, effectiveness, STAB and STAB/effectiveness if terastallized, poke-env's damage
  range vs the opponent's active (with estimated stats), KO flags, and static move properties.
- Field token (67): weather and turns (from the log: poke-env restarts the count at every
  upkeep message), terrain, Trick Room, gravity, both sides' hazards/screens/Tailwind with turns,
  turn, tera availability, remaining counts, forced switch / trapped / reviving, speed share, best
  damage each way.

## Actions and masks
0-3 use available move i, 4-7 the same with Terastallization, 8-13 switch to `battle.team` slot k
(or revive it with Revival Blessing). Masks are legality only: a move slot needs a move, tera
also `battle.can_tera`, a switch needs that Pokémon in `available_switches`. Tera is masked with
Struggle and Recharge.

## Network (1.08M parameters)
Shared embeddings (species 48, move 32, ability/item/type 16). Pokémon, move and field encoders
(2-layer MLPs to 128), all tokens of a type in one call. Context: field, own active, opponent
active, mean and max of each team → LayerNorm → MLP → 256. Heads: move MLP([move token, context])
→ (use, tera + use); switch MLP([own token k, opponent active, context]) → 1; value MLP(context).
Orthogonal init, 0.01 gain on the policy logits. 0.27 ms per batch-1 decision on one CPU thread.

## Training loop
- W worker processes (forkserver, one torch thread), each with one `RLEnvV20` on a shared
  Showdown server. Each update: the learner sends weights and a quota (steps_per_update / W);
  the worker plays whole games until it has the quota, computes GAE, returns the samples.
  No per-step lockstep; the only wait is at the end of the update (for the last games to finish).
- Opponents per game: 10% SimpleHeuristics; of the rest, 50% the live policy with both sides
  recorded (two-sided self-play), 50% uniform over the pool (v20 snapshots every 1M, plus the five
  SB3 seed models). Sampled (not greedy) actions for all policies.
- PPO as SB3's MaskablePPO: clipped surrogate, SB3's value clipping (clamps each value's change),
  per-minibatch advantage normalization, entropy bonus, grad clipping, plus the zero-avoiding term
  `zero_avoid_coef * KL(uniform over legal || pi)` (0.005). Update on the Apple GPU (MPS) when
  available: 2.7x the M3's CPU for this network.
- Evals: every 1M steps, 500 deterministic games vs SimpleHeuristics in a separate process with a
  fresh env, closed without waiting; training continues meanwhile. Snapshots in
  `models/eval_snapshots_<version>/`; the best one is copied to `_best.pt`.
- Checkpoints: `models/ppo_pokemon_6v6_<version>_latest.pt` every 200K steps and at each eval
  (model, optimizer, config, step, games, eval state; 13 MB). A run resumes from it automatically,
  including evals that were still running.
- Watchdogs: a battle with no update for 60 s raises `EnvTimeout` and the worker rebuilds its env;
  a worker silent for 30 minutes in one update is restarted.

## Running
```
cd ../pokemon-showdown && for p in 8000 8001 8002 8003; do node pokemon-showdown start --no-security --port $p > /tmp/showdown_$p.log 2>&1 & sleep 2; done
cd ../pokemon-rl
python3 -m training.ppo_v20 --workers 6 --servers 3 --stop-at 10000000     # eval on port 8003
python3 -m eval.ppo_test --model models/ppo_pokemon_6v6_v20_best.pt --opponents simple --battles 1000 --port 8123
python3 -m eval.ppo_test --model models/ppo_pokemon_6v6_v20_best.pt --opponents model \
    --opp-model models/ppo_pokemon_6v6_v19_best.zip --battles 1000 --seat both --port 8123
```
`--seat both` plays the given number of games in each seat.
